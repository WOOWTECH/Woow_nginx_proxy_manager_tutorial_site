第 3 章

首次登入與帳號安全

第一次登入只做一件優先事項：立刻淘汰公開的預設電子郵件與密碼，再驗證新憑證確實可用。

登入前先封閉管理面

WOOWTECH README 明列初始登入資料為 admin@example.com／changeme，並要求登入後立即更改。上游 NPM 2.12.4 的初始化程式也以這組值建立第一位管理員；它們是公開資訊，不是祕密。

  • 確認你正從可信任區網連線，而不是行動網路或公開 Wi-Fi。
  • 確認路由器沒有 WAN TCP 81 轉送，防火牆也沒有讓任意網際網路來源碰到 81。
  • 關閉錄影、直播與會同步表單內容的工具；密碼、電子郵件、IP 與登入畫面都視為敏感資料。
  • 先準備可信任的密碼管理器，但不要把新密碼貼入聊天、issue、截圖或一般筆記。
先封閉，再登入。如果 TCP 81 已公開，不要只靠「等一下會改密碼」承擔風險；先移除公開入口，才繼續本章。

使用預設值登入一次

  1. 開啟正確的 Web UI

    從 Home Assistant add-on 頁面選「OPEN WEB UI／開啟 Web UI」，或在可信任區網開啟 http://<HA區網位址>:81。核對位址是你自己的 NPM，不要從搜尋結果進入登入頁。

  2. 輸入初始電子郵件

    輸入 admin@example.com。這個值只能用於首次加固，不要保留成日常登入識別。

  3. 輸入初始密碼

    輸入 changeme 並登入。不要讓瀏覽器把這個預設值儲存為正式密碼。

  4. 直接前往帳號設定

    登入成功後不要先建立 Proxy Host、憑證或其他使用者；先完成下一節的帳號詳細資料與密碼變更。

只使用一次：若預設帳密登入失敗，不要反覆猜測或重設資料庫；先確認是否已有管理者完成初始化。

立即更改電子郵件

  1. 開啟 Users

    在 NPM 主選單開啟 Users，找到目前的 Administrator 帳號。

  2. 編輯詳細資料

    開啟該帳號的動作選單，選 Edit Details（繁體中文介面可能顯示對應翻譯）。

  3. 換掉預設電子郵件

    把 admin@example.com 改成你控制且不與他人共用的登入電子郵件，並確認姓名與暱稱不洩漏不必要資訊。電子郵件也是敏感資料，不要放進截圖。

  4. 儲存並接續改密碼

    按 Save。add-on 所用的 NPM 2.12.4 介面不允許保留預設電子郵件；從預設帳號儲存新資料後，會接著開啟密碼視窗。

若介面改版後流程不同，原則不變：先在目前管理員的詳細資料更改預設電子郵件，再使用同一帳號的 Change Password 功能。不要建立第二個管理員來規避加固。

立即設定新密碼

  1. 確認正在修改自己

    密碼視窗應顯示目前管理員。若不是，取消操作並回到 Users 選擇正確帳號。

  2. 輸入目前密碼

    首次加固時，目前密碼是剛才使用的預設值。介面要求修改自己的密碼時提供 Current Password。

  3. 產生唯一的新密碼

    用密碼管理器產生長且隨機、未在其他網站使用的密碼。NPM 2.12.4 前端欄位最低長度為 8 個字元，但最低門檻不等於安全建議。

  4. 確認後儲存

    在 New Password 與 Confirm Password 輸入同一個新值並儲存。只把新密碼保存在可信任的密碼管理器，不要抄進公開或會同步的文件。

電子郵件與密碼都要換：只改其中一個並不算完成。最終狀態必須不再使用 admin@example.com，也不再接受 changeme。

登出後驗證

  1. 主動登出

    完成儲存後使用 NPM 的登出功能，不要只關閉分頁。

  2. 以新憑證登入

    重新開啟同一個可信任區網 Web UI，從密碼管理器填入新的電子郵件與新密碼。

  3. 確認帳號身分

    回到 Users，確認目前管理員顯示新的電子郵件，且管理功能仍可用。不要截取含真實資料的畫面。

  4. 確認預設值失效

    在私人瀏覽視窗對正確的區網位址測試一次舊的預設組合，應無法登入。避免連續重試；一次足以確認。

通過條件是「新憑證成功、預設憑證失敗」。若只驗證新憑證可用，仍無法證明預設密碼已淘汰。

維持管理面邊界

項目安全作法不安全作法
TCP 81只從可信任區網或受控管理通道存取路由器 WAN 轉送、任意來源防火牆規則
登入電子郵件使用你控制的非預設識別，存於可信任保管庫留用 admin@example.com 或出現在公開截圖
管理密碼長、隨機、唯一，交由密碼管理器保管重複使用、分享、寫入 Proxy Host 設定或一般筆記
工作階段共用裝置用完即登出，管理裝置保持更新在公用電腦保存登入或長期不鎖定裝置
求助資料只貼必要錯誤並遮罩上傳完整記錄、憑證、Token、網域或公私有 IP

改完密碼不會把管理介面變成適合公開的服務。TCP 81 仍不可暴露到網際網路，後續章節也不會以公開 Proxy Host 包裝它。

留下安全的管理紀錄

你可以留下不含祕密的維運紀錄，例如「預設帳號已於某日停用」「管理面僅限可信任網段」「下次權限檢查日期」。不要在紀錄中寫出真實電子郵件、密碼、完整網域或 IP。

  • 密碼與登入電子郵件：只存在受保護的密碼管理器項目。
  • DNS API Token：日後若使用 DNS Challenge，獨立保存並給最小權限。
  • 憑證與私鑰：交由 NPM／備份機制保護，不貼進 issue。
  • 記錄檔：只摘錄與錯誤直接相關的少量行，先遮罩網域、公私有 IP、帳號、Token 與憑證內容。
完成標記：可以記「新憑證登入成功、預設組合失敗、81 無 WAN 入口」，但不要記下新憑證本身。

登入與加固排錯

問題一：預設帳密無法登入

先確認網址是自己的 NPM TCP 81、鍵盤大小寫與輸入法正確。若此實例曾使用過，可能已建立管理員；不要為了恢復預設值而刪除資料庫。

問題二：儲存時拒絕 admin@example.com

這是 NPM 2.12.4 的預期保護：預設電子郵件不允許繼續保留。改成你控制的非預設登入電子郵件再儲存。

問題三：新密碼與確認值不一致

清空兩欄，從密碼管理器重新填入同一筆產生值。不要為方便而改用短或重複使用的密碼。

問題四：Current Password 顯示無效

確認你修改的是自己的帳號，並輸入目前仍有效的密碼。若電子郵件已改但密碼視窗中斷，回到 Users 的該帳號選 Change Password。

問題五：改完後新憑證仍無法登入

先停止連續嘗試，確認新電子郵件是否已儲存、密碼管理器項目是否更新，再從可信任區網重試。不要在公開頻道貼出表單或完整記錄。

問題六：從外網竟然可以打開 81

這不是便利功能，而是暴露。先移除路由器 WAN 轉送與過寬防火牆規則，再檢查是否還有公開 DNS 或代理路徑。

常見問題

可以只改密碼，不改預設電子郵件嗎？
不可以。任務目標是同時淘汰公開的預設登入識別與預設密碼；NPM 2.12.4 的帳號表單也不允許保留 admin@example.com。
密碼至少 8 個字元就夠嗎？
8 個字元是該版前端欄位的最低門檻，不是安全目標。請使用密碼管理器產生更長、隨機且唯一的密碼。
改完強密碼後能公開 TCP 81 嗎？
不能。強密碼不會消除管理介面的漏洞、暴力嘗試與設定錯誤風險；81 仍只限可信任區網或受控管理通道。
忘記新密碼時可以直接刪除資料庫重來嗎？
不要。刪除資料庫可能同時失去 Proxy Host、使用者與其他設定。先保留現況與備份，查閱對應版本的官方支援資訊後再採取恢復程序。
