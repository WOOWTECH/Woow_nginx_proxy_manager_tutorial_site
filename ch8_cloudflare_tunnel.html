第 8 章

Cloudflare Tunnel 搭配 NPM

讓 cloudflared 主動連到 Cloudflare，外部 HTTPS 停在 Cloudflare 邊緣，NPM 留在內網負責依網域轉送，不必在路由器開放 80、443 或 81。

不用把家中入口直接放上公網

Cloudflare Tunnel 由內部的 cloudflared 建立 outbound-only 連線，Cloudflare 官方說明不需要 publicly routable IP。這很適合沒有固定公開 IP、位於 CGNAT，或不想維護路由器入站轉送的家庭環境。

推薦分工：Cloudflare 接受公網 HTTPS，Tunnel 把請求送到內網 NPM 的 HTTP 入口，NPM 再依 Host 名稱轉送至 Home Assistant、NAS 或其他內部服務。
管理安全基線：預設 admin@example.com／changeme 必須立即更改。Cloudflare Tunnel 只能發布業務服務，不可發布 NPM port 81；port 81 也不可做路由器轉送。

建置前的清單

  1. 確認 Cloudflare 管理該網域

    你需要能在自己的 Cloudflare 帳號建立 Tunnel 與公開 hostname。網域、帳號 ID、zone ID 都視為敏感資訊。

  2. 準備可長期執行的 connector

    在與 NPM 網路互通的可信任設備執行 cloudflared。本章不限定特定第三方 add-on；請使用 Cloudflare 官方支援的安裝方式或你已審核的套件。

  3. 確認內網路徑

    connector 必須能存取 NPM port 80，NPM 必須能存取上游服務。這兩段只需內網可達，不代表要開放給所有 LAN 裝置。

  4. 盤點既有轉送

    若原本已使用公網 80／443，先記錄依賴與回復方式。確認所有 hostname 已遷移並測試完成後，才依你的變更流程停用舊規則；不要在不確定影響時直接刪除。

先讓 NPM 會依網域路由

  1. 新增 Proxy Host

    在 NPM 選擇 Hosts → Proxy Hosts → Add Proxy Host，Domain Names 填入稍後要在 Tunnel 發布的完整 hostname。真實網域不要出現在教學截圖或公開工單。

  2. 設定內部上游

    Forward Hostname／IP 與 Forward Port 填入服務的私有位址及連接埠，Scheme 依上游實際提供的 HTTP 或 HTTPS 選擇。私有 IP 仍是敏感拓樸資料。

  3. 暫時不要申請公有憑證

    推薦 Tunnel Service URL 連 NPM 的 HTTP port 80，外部 TLS 由 Cloudflare 處理；此時 NPM 不需要為外部瀏覽器申請 Let's Encrypt 憑證。

  4. 不要啟用 Force SSL

    Cloudflare 會以 HTTP 連到 NPM 時，Force SSL 可能讓同一個外部 HTTPS URL 反覆重新導向。先保持關閉，外部 HTTP 轉 HTTPS 由 Cloudflare 邊緣設定處理。

建立並啟動 connector

  1. 在 Cloudflare 建立命名 Tunnel

    由 Cloudflare Dashboard 的 Zero Trust／Networks／Tunnels 流程建立 Tunnel；介面名稱可能改版，請以當期官方文件為準。

  2. 選擇 connector 環境

    依執行平台採用 Cloudflare 顯示的官方安裝方式。畫面中的 tunnel token 就是可啟動 connector 的機密，不可貼到聊天、命令記錄、截圖或版本庫。

  3. 安全地提供 token

    把 token 存入該平台的 secret／受保護設定，限制只有 connector 程序可讀。若曾外洩，立即在 Cloudflare 輪替或撤銷，不要只刪除訊息。

  4. 確認狀態為 Healthy

    connector 需要對外 DNS，並依 Cloudflare 官方防火牆文件連到 port 7844（QUIC 使用 UDP、HTTP/2 使用 TCP）。不需要任何公網入站規則。

把公開 hostname 指向 NPM

  1. 新增 Published application

    在該 Tunnel 新增公開 hostname，Subdomain 與 Domain 合起來必須和 NPM Proxy Host 的 Domain Names 完全相同。

  2. Service Type 選 HTTP

    URL 填 NPM 在內網可達的位址與 port 80，例如 http://<NPM 私有位址>:80。這只是格式示意，不要把真實私有 IP 提交到公開文件。

  3. 儲存並確認 DNS

    Cloudflare 會把 hostname 路由到 Tunnel；官方文件說明其本質是指向 <UUID>.cfargotunnel.com 的 CNAME。同一個 Tunnel 可服務多個 hostname。

  4. 每個 hostname 都在 NPM 建一筆

    要新增服務時，同時新增 Published application 與對應的 NPM Proxy Host。不要把所有未匹配 hostname 導到管理介面。

路由關鍵：Cloudflare 以公開 hostname 收到請求，NPM 也以相同 Host 選擇 Proxy Host；兩邊字串不一致時，通常會落到預設頁面或 404。

分清楚外部 TLS 與內部回源

區段推薦設定理由與限制
瀏覽器 → CloudflareHTTPS；在 Cloudflare 邊緣將 HTTP 轉 HTTPS瀏覽器驗證 Cloudflare 為該 hostname 提供的邊緣憑證
Cloudflare Tunnel → NPM隔離內網中的 HTTP port 80設定簡單且不需 NPM 公有憑證，但這一段未加密，必須限制於可信任網路
NPM → 內部服務依服務能力選 HTTP 或 HTTPSNPM 的 Scheme 必須與上游實際協定一致
若內網也要求加密：可以把 Tunnel Service URL 改為 NPM HTTPS，但必須替 NPM 配置正確、可由 connector 驗證且名稱相符的憑證。不要用停用 TLS 驗證來掩蓋憑證錯誤。
Force SSL 的位置只能清楚分工：HTTP Service URL 回源時，NPM 保持 Force SSL 關閉；外部 HTTP 轉 HTTPS 在 Cloudflare 處理。不要兩邊憑直覺全開。

Tunnel 不是完整的身分驗證

  • 永不發布 port 81：Tunnel 公開 hostname 只指向 NPM port 80／443 的代理入口，不得指向管理介面。
  • 每個 hostname 最小暴露：只發布真正要從公網使用的服務。資料庫、SSH、NAS 管理頁不應因為 Tunnel 好設定就一併公開。
  • 敏感值全程遮罩：網域、公開／私有 IP、tunnel token、DNS API token、密碼、憑證與完整 log 都不可公開。
  • 需要使用者身分時加 Cloudflare Access：Tunnel 只建立傳輸路徑；服務若不該匿名使用，仍要在應用、Cloudflare Access 或第 9 章的 Access List 加上合適控制。
  • 限制 connector 與 NPM 的網路：只允許必要的 connector 到 NPM、NPM 到上游流量，不要把整個內網視為可信任。

從內到外逐段驗證

  1. 測試 NPM 到上游

    先從內網確認上游服務可達，Scheme 與 port 正確。不要因為 502 就開放更多公網連接埠。

  2. 測試 Host 路由

    在可信任內網以該 hostname 請求 NPM，確認會落到正確 Proxy Host，而不是預設站台。

  3. 確認 connector 健康

    在 Cloudflare 檢查 Tunnel 是否有連線中的 connector。只記錄狀態與時間，不公開 UUID、token 或完整 diagnostic log。

  4. 由外部測試 HTTPS

    使用行動網路開啟公開 hostname，確認 HTTPS、登入、WebSocket 與必要功能；再測 HTTP 是否在 Cloudflare 邊緣轉向 HTTPS。

  5. 確認路由器沒有不必要入站

    驗證完成後，依變更流程檢查公網 80、443、81 都沒有轉送至 NPM。若舊服務仍依賴規則，先遷移並保留可回復方案。

Cloudflare Tunnel 常見問題

這個架構需要路由器轉送 80 或 443 嗎？
不需要。cloudflared 主動向 Cloudflare 建立 outbound-only 連線；推薦拓樸不使用公網入站 80、443，也絕不公開 81。
沒有公開 IP 或在 CGNAT 後面可以用嗎？
可以。Cloudflare 官方將 Tunnel 定位為不需要 publicly routable IP 的連線方式，但 connector 仍需可對外連線與解析 DNS。
為什麼 NPM 不勾 Force SSL？
本章讓 Tunnel 以 HTTP 連到 NPM。NPM 若強制回 HTTPS，Cloudflare 下次仍以 HTTP 回源，可能造成重新導向迴圈；外部轉向應放在 Cloudflare 邊緣。
一個 Tunnel 可以發布多個服務嗎？
可以。Cloudflare 官方文件說明多個 DNS 記錄可以指向同一 Tunnel；每個公開 hostname 仍應在 NPM 建立明確對應的 Proxy Host。
有 Tunnel 就不需要服務登入嗎？
不是。Tunnel 解決連線路徑，不會自動替每個應用建立使用者身分驗證。請保留應用登入，或按需求加入 Cloudflare Access、NPM Access List。
