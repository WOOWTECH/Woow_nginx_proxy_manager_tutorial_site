WoowTech · Nginx Proxy Manager Skill 手冊

教 AI Agent 維運 NPM，但不交出失控的權限

好的 Skill 不是一組神奇指令，而是可重複、可稽核、可回復的工作流程。這本手冊用六種模式，讓 Agent 協助你盤點資產、追蹤憑證、稽核存取、驗證備份、診斷日誌與安全自動化。

先分清楚：模式不是現成工具

本頁的「Skill 模式」是可重複使用的 SOP：定義輸入、允許的資料來源、分析步驟、輸出格式與安全閘門。你可以把它寫進 Agent 支援的 Skill／指令檔，也可以當人工 Runbook 使用。

本頁沒有推薦未查證的第三方 Skill 套件。沒有虛構 repo、下載數或星數。Nginx Proxy Manager 官方網站、官方文件與官方 GitHub 專案可作為產品行為的查證來源；你實際採用的 Agent、備份工具、監控平台與第三方整合，仍要自行驗證版本、來源與權限。

證據來源與 API 界線

Agent 每次執行前都要辨識 NPM 版本與部署方式。NPM 的網頁前端會呼叫介面，但路徑與 schema 可能隨版本改變，不能把網路文章中的 endpoint 當成穩定公開 API。只有在該版本官方原始碼、實際 schema 或你核准的整合文件能驗證方法、欄位、回應與授權時，Skill 才能呼叫；否則退回唯讀網頁操作指引或經核准的資料匯出。

來源可做的事限制
NPM 網頁介面人工確認清冊、關聯與設定狀態不要讓 Agent 以脆弱的畫面自動化直接做大量寫入
版本相符且已驗證的介面結構化唯讀盤點；核准後執行有限變更固定版本與 schema，最小權限，記錄請求結果，不記錄祕密
主機／容器日誌建立錯誤時間線、比對 upstream 與 TLS 問題先遮罩 Cookie、Token、查詢字串與個資
備份檔驗證清單、校驗值、可解密與隔離還原不得把資料庫或私鑰送到外部模型
DNS 與網路探測查 A／AAAA／CNAME、TLS、允許範圍內的連通性NPM 不管理一般 DNS；探測範圍需事先授權

六種可重複的 Skill 模式

1. NPM 資產清冊

預設權限：唯讀 · 建議頻率：每日或每週

把 Proxy Hosts、Redirection Hosts、Streams、Access Lists、憑證與 NPM 使用者整理成同一份清冊，讓你知道公開了什麼、轉到哪裡、誰能管理。

  • 輸入：核准的 NPM 實例、環境標籤與唯讀資料來源。
  • 輸出：資源 ID／名稱、網域或連接埠、後端、TLS、Access List、啟用狀態及資料時間。
  • 檢查：重複網域、連接埠衝突、無憑證公開主機、孤兒 Access List 與未知擁有者。
  • 禁止：盤點流程不得順手修正、停用或刪除。

2. 憑證到期守望

預設權限：唯讀 · 建議頻率：每日

依到期天數分級，不只看日期，也確認網域解析、憑證涵蓋名稱、使用中的主機與最近續期錯誤。

  • 輸出：7／14／30 天門檻、SAN、簽發者、引用主機、續期前置條件。
  • 告警去重：以憑證識別值與到期日形成事件鍵，避免每天重複製造新事件。
  • 安全：永不輸出私鑰或 DNS API Token；自動重試前要限制次數，避免 CA rate limit。

3. Access List 與帳號稽核

預設權限：唯讀 · 建議頻率：每週及每次變更後

分開檢查 NPM 管理使用者、Access List 的來源規則，以及 Access List 內的 HTTP 基本驗證帳號，避免把三者混為一談。

  • 檢查：過寬 CIDR、規則順序、未套用清單、共用管理帳號、停用狀態與責任人。
  • 輸出：證據、風險等級、受影響主機、建議差異與鎖住自己的風險。
  • 限制：不讀出密碼；收緊規則前必須確認備援管理路徑。

4. 備份與還原驗證

預設權限：備份儲存區唯讀 · 建議頻率：每次備份後驗證，每季演練

依部署方式辨識資料庫、設定與憑證持久化範圍，檢查加密、校驗值、保留期及離機副本，並在隔離環境演練還原。

  • 成功條件：可解密、內容完整、版本相容、隔離實例可啟動、代表性主機設定可讀。
  • 輸出：RPO／RTO、最後成功時間、校驗結果、缺漏與演練證據。
  • 禁止：未確認環境識別與快照前，絕不覆寫正式資料。

5. 日誌診斷

預設權限：日誌唯讀 · 觸發：502、504、TLS 或轉址事件

先建立時間線，再按 DNS、入口、NPM、網路與後端分層。診斷必須把「觀察到的事實」與「待驗證假設」分開。

  • 502：優先核對 upstream 位址、連接埠、協定、名稱解析、TLS 與後端拒絕。
  • 504：比對後端耗時、網路遺失與逾時；不能只用放大 timeout 掩蓋根因。
  • 隱私：輸出前遮罩 Authorization、Cookie、Token、查詢字串個資與內部祕密。

6. 安全變更自動化

預設權限：唯讀；單項短效寫入權限需另行核准

把「偵測、提案、核准、執行、驗證、回復」做成狀態機。每次只處理明確資源，使用 idempotency 檢查避免重複建立。

  • 提案：顯示資源識別、修改前後差異、影響、依賴、回復與驗證方式。
  • 核准：確認文字需綁定目標、差異雜湊與有效期限；舊核准不能套到新差異。
  • 執行：只用已驗證介面與最小權限；寫入後立即讀回比對。
  • 失敗：停止後續批次、保留證據、依核准方案回復，不自行擴大修復。

每個 Skill 都要有安全合約

合約項目最低要求
範圍列出允許的 NPM 實例、資源類型、網域與環境；預設拒絕未列項目。
身分與權限獨立 Agent 身分、最低權限、短效祕密；不可共用你的管理 Cookie。
資料處理祕密不進提示詞、不進日誌、不送外部模型；報告先遮罩再保存。
變更閘門預覽差異、影響、回復、明確人工確認；刪除與還原需更強的指定名稱確認。
可稽核性記錄誰、何時、對哪個資源、依哪份核准、得到什麼結果；不要記錄密碼與 Token。
停止條件版本不符、schema 無法驗證、備份失敗、目標漂移或驗證失敗時立即停止。
高風險動作不應全自動：刪除 Proxy Host／憑證／使用者、覆寫資料庫、正式環境還原、批次變更 Access List，以及升級主要版本，都必須由你核准並保留可回復點。

從唯讀開始的四個自動化層級

層級Agent 可以做什麼升級條件
L0 建議閱讀你提供的脫敏資料，產生清單與操作步驟。輸出穩定，沒有杜撰欄位或工具。
L1 唯讀定期盤點、到期檢查、日誌查詢與告警。來源已驗證、權限隔離、敏感資訊遮罩、誤報可接受。
L2 核准後寫入針對單一資源執行已預覽、可回復的變更。測試環境通過、差異綁定核准、寫後驗證與回復演練完成。
L3 低風險自動修復只處理預先核准、範圍狹窄且冪等的事件。有錯誤預算、速率限制、停止開關與人工值班；高風險動作仍排除。

可攜式 Skill 規格範本

不同 Agent 的檔名與 metadata 格式不一定相同，以下是中立範本，不代表任何特定產品的安裝規格：

名稱：npm-certificate-auditor
目的：唯讀盤點 NPM 憑證，依到期日與引用關係產生報告

輸入：
- NPM 實例識別與環境標籤
- 經驗證、版本相符的唯讀資料取得方式
- 告警門檻：7、14、30 天

前置檢查：
1. 驗證目標實例、版本、部署方式與唯讀權限
2. 驗證介面 schema；不能驗證就停止，不猜 endpoint
3. 確認輸出位置不會洩漏祕密

步驟：
1. 取得憑證中繼資料與主機引用關係
2. 計算到期天數，核對網域名稱與最近續期錯誤
3. 依門檻分級，產生含資料時間與證據的報告
4. 遮罩 Token、Cookie、私鑰與不必要個資

輸出：
- 摘要、風險項、證據、建議人工處置
- 不直接申請、續期、刪除或重新指派憑證

停止條件：
- 版本或 schema 不符
- 回應缺少必要欄位
- 目標不是核准的實例
- 取得資料時要求提升權限

導入前檢查表

  • 你能指出每個資料欄位來自哪個已驗證來源，而不是 Agent 猜測。
  • Agent 有獨立、最低權限身分；祕密使用核准的祕密管理方式且可輪替。
  • 清冊、憑證、Access List、備份與日誌報告都會標示實例及資料時間。
  • 測試資料涵蓋 API 失敗、版本漂移、部分回應、重複執行與超時。
  • 所有寫入都有具體 diff、人工核准、寫後驗證、稽核記錄與回復方案。
  • 刪除、正式還原與批次權限變更永遠不在無人值守自動化範圍。
  • 你已設定停止開關，且知道 Agent 失敗時由誰接手。
先跑 L1 至少一個完整維運週期。確認報告準確、沒有洩密且誤報可控後，再挑一項低風險、可回復的任務進入 L2，不要一次把所有管理權交給 Agent。
