Chapter 7

Request and manage SSL certificates

Compare Let's Encrypt HTTP-01 with DNS-01, put a certificate on your Proxy Host, then turn on Force SSL, HSTS and a renewal check safely.

Pick the right challenge first

Let's Encrypt issues a certificate only once it has confirmed that you control the domain. Nginx Proxy Manager (NPM) can prove that over HTTP or over DNS; which one you pick depends on port 80, the kind of domain and your DNS provider, not on which button is more convenient.

What "done" looks like: a browser opens your service over HTTPS, HTTP redirects to HTTPS the way you planned, and you know that renewal still needs the challenge conditions you started with.
Admin security baseline: if you are still on admin@example.com / changeme, you must change it immediately. Port 81 must only be reachable from a trusted LAN or a controlled management channel, and must never be forwarded to the public internet.

Choosing between HTTP-01 and DNS-01

ItemHTTP-01DNS-01
ChallengeLet's Encrypt reads the challenge content over HTTPLet's Encrypt queries a temporary DNS TXT record
Network conditionsThe domain must point at NPM, and public TCP 80 must be able to reach NPMNo need to expose 80/443 to the internet
Wildcard certificateNot supportedSupported, for example *.example.invalid
Secrets requiredNo DNS API token neededA DNS provider API credential is needed
Typical useTraditional port forwarding, a single hostnameCGNAT, port 80 unavailable, wildcards or a Tunnel architecture
What HTTP-01 always requires: Let's Encrypt's own documentation states that this challenge can only be completed on port 80, and that it cannot be used to get a wildcard certificate. Once issuance succeeds, the HTTP challenge still has to stay reachable at renewal time.

Check before you request

  1. Confirm the account and the admin surface

    Change the default credentials first, and keep port 81 reachable only from a trusted network. Do not publish the admin interface through a public-facing Proxy Host.

  2. Check the domain

    Write the fully qualified domain name down using your own redacted placeholder. Do not paste the real domain, public or private IPs, or your internal topology into a public help forum.

  3. Confirm the NPM user's email

    The upstream NPM code requires a user account to hold a valid email before it will request a certificate from Let's Encrypt. That email is personal data too.

  4. Pick one path you can keep renewing

    HTTP-01 means keeping the port 80 challenge path in place for the long term; DNS-01 means keeping a valid, least-privilege DNS token for the long term. Do not test only the first issuance.

Request a certificate with HTTP-01

  1. Finish DNS and forwarding

    Resolve the domain to your public IP, and forward only router TCP 80 and 443 to the host NPM runs on. Do not forward TCP 81.

  2. Create a working Proxy Host first

    In Hosts → Proxy Hosts, create a host whose domain is exactly the certificate domain, and confirm it is reachable over HTTP from outside. The official NPM certificate help states that HTTP validation needs a Proxy Host that is reachable over HTTP and points at this Nginx.

  3. Request it on the SSL tab

    Edit that Proxy Host, choose to request a new Let's Encrypt certificate on the SSL tab, enter a valid email, agree to the terms of service, and leave DNS Challenge unchecked.

  4. Save it, then verify from an external network

    Test over mobile data and confirm the certificate subject covers that domain. Before you share a test result or an error record, redact the domain, the IPs, the certificate details and full logs.

Closing port 80 is not hardening: with HTTP-01, the official NPM documentation requires the Proxy Host to stay reachable over HTTP so renewal can work. If you cannot accept that, use DNS-01 instead.

Request a certificate with Cloudflare DNS-01

  1. Create a dedicated API token

    In Cloudflare, create a token that only Certbot uses, authorized to edit DNS on the target zone and nothing more; do not use the over-privileged Global API Key. The Certbot Cloudflare plugin's own documentation also recommends an API token that can be restricted to specific domains.

  2. Choose DNS Challenge

    Request the Let's Encrypt certificate on the Proxy Host's SSL tab, check Use a DNS Challenge, and set DNS Provider to Cloudflare.

  3. Fill in the token format

    In Credentials File Content, use the token field the Cloudflare plugin supports. What follows is only a dummy value; do not replace it with a real token and then screenshot it or commit it to Git:

    dns_cloudflare_api_token = <dns-token-scoped-to-the-target-zone>

  4. Wait for DNS propagation, then save

    Start with the default propagation wait; raise it step by step only when you have confirmed the TXT record has not propagated yet. Once issuance is done, do not delete the token NPM needs, or automatic renewal will fail.

A token is a secret: do not put it in a browser bookmark, a tutorial screenshot, a chat log, Git or a support ticket. If you suspect a leak, revoke it at your DNS provider immediately, create a new least-privilege token, and then update NPM.

Apply the certificate and Force SSL

  1. Select the right certificate

    Edit the Proxy Host and pick the certificate that covers that fully qualified domain name under SSL Certificate. Do not assume a certificate that does not include the hostname will work anyway.

  2. Test HTTPS first

    After saving, open https://<your-domain> directly and confirm the upstream service works, the certificate chain is valid, and there is no redirect loop.

  3. Then turn on Force SSL

    Once HTTPS is confirmed good, check Force SSL. NPM's upstream template loads the forced-HTTPS configuration when a certificate is already in place.

  4. Test the HTTP entry point

    Open http://<your-domain> and confirm it redirects to HTTPS on the same host, not to the wrong domain and not into an endless loop.

The Cloudflare Tunnel exception: if the Tunnel's internal Service URL is NPM's http://…:80, do not turn on Force SSL in NPM, or Cloudflare may keep getting an HTTPS redirect every time it connects back to the origin over HTTP. Handle the HTTP-to-HTTPS redirect at the Cloudflare edge instead; Chapter 8 covers it in full.

Turn HSTS on last

HSTS uses Strict-Transport-Security to tell a browser that from now on the site may only be reached over HTTPS. NPM's upstream template adds the header only when a certificate is selected and both Force SSL and HSTS are enabled, and the default lifetime is two years.

  1. Confirm HTTPS works for the long term first

    Confirm that the certificate covers the right domain, that the renewal path works and that everything you need is available over HTTPS, before you enable HSTS.

  2. Leave Include Subdomains unchecked at first

    If any subdomain does not support HTTPS yet, includeSubDomains makes the browser force it up to HTTPS too, and it stops working. Take stock of every subdomain one by one first.

  3. Start on a test host

    Test browsers, APIs and mobile apps on a non-critical subdomain first, then decide whether to apply it to a production service.

HSTS is not something to try out: a browser remembers the policy until max-age expires, and turning the NPM option off does not make a visitor's browser forget it right away. Enable it only when both HTTPS and renewal are reliable, and be even more conservative with Include Subdomains.

Confirm automatic renewal really works

  1. Check the expiry date under Certificates

    Record what the certificate covers and when it expires, but keep the real domain and the certificate contents out of any public document. The upstream NPM code checks Let's Encrypt certificates on a schedule and handles the ones that are about to expire.

  2. Keep the original challenge conditions

    For HTTP-01, keep the DNS pointing where it does and public port 80 in place; for DNS-01, keep a valid, least-privilege DNS token. When a token is rotated, update NPM with it.

  3. Check failure messages regularly

    Read the add-on and certificate logs only from a trusted admin surface. Before you share troubleshooting data, redact domains, public and private IPs, tokens, certificates, accounts and full logs.

  4. Schedule a human review before expiry

    Automation is not maintenance-free. A change to DNS provider permissions, to a router rule or to the domain's own renewal can all break the next renewal.

SSL FAQ

Once HTTP-01 has succeeded, can I close port 80?
Not recommended. The official NPM certificate help states that a Proxy Host using HTTP validation must keep offering HTTP access for renewal to work. If you do not want port 80 exposed, use DNS-01 instead.
Can a wildcard certificate use HTTP-01?
No. Let's Encrypt states explicitly that HTTP-01 does not support wildcards; use DNS-01.
Are Force SSL and HSTS the same thing?
No. Force SSL is the server redirecting an HTTP request to HTTPS; HSTS is a policy the browser remembers: from then on, only HTTPS may be used.
With Cloudflare Tunnel, does NPM still need a public certificate?
If the Tunnel connects over HTTP to NPM port 80 on an isolated LAN, what the browser sees is the Cloudflare edge certificate, so NPM does not necessarily need a public certificate. If you move the origin hop to HTTPS, you then have to validate the origin certificate properly.
Can I paste a DNS token into a support ticket and ask someone to look into it?
No. Tokens, certificates, domains, IPs and full logs are all sensitive data. Revoke any token that has leaked, and hand over only a redacted summary of the error.
