Chapter 7

申請與管理 SSL 憑證

比較 Let's Encrypt HTTP-01 與 DNS-01，替 Proxy Host 配上憑證，再安全地啟用 Force SSL、HSTS 與續期檢查。

先選對驗證方式

Let's Encrypt 必須先確認你控制網域，才會簽發憑證。Nginx Proxy Manager（NPM）可透過 HTTP 或 DNS 驗證；選擇取決於 port 80、網域型態與 DNS 供應商，而不是哪一個按鈕比較方便。

本章完成條件：瀏覽器能以 HTTPS 開啟你的服務、HTTP 會依規劃轉向 HTTPS，而且你知道續期仍需要原本的驗證條件。
管理安全基線：若仍使用 admin@example.com／changeme，請先立即更改。port 81 只能由可信任的內網或管理通道存取，絕不可轉送到公網。

HTTP-01 與 DNS-01 怎麼選

項目HTTP-01DNS-01
驗證方式Let's Encrypt 以 HTTP 讀取驗證內容Let's Encrypt 查詢臨時的 DNS TXT 記錄
網路條件網域須指向 NPM，公網 TCP 80 必須可到達 NPM不需要把 80／443 對外開放
萬用字元憑證不支援支援，例如 *.example.invalid
所需機密不需要 DNS API token需要 DNS 供應商 API 憑證
常見用途傳統 port forwarding、單一主機名稱CGNAT、port 80 不可用、萬用字元或 Tunnel 架構
HTTP-01 的固定條件：Let's Encrypt 官方說明此挑戰只能在 port 80 完成，也不能簽發萬用字元憑證。申請成功後，續期時仍要維持 HTTP 驗證可達。

申請前先檢查

  1. 確認帳號與管理面

    先更換預設登入資料，限制 port 81 只在可信任網路可達。不要用對外 Proxy Host 公開管理介面。

  2. 核對網域

    以你自己的遮罩值記下完整主機名稱。不要把真實網域、公開／私有 IP 或內部拓樸貼到公開求助區。

  3. 確認 NPM 使用者 email

    NPM 上游程式要求使用者帳號具有有效 email，才能向 Let's Encrypt 申請憑證。這個 email 也屬個人資料。

  4. 只選一條可續期的路

    HTTP-01 要長期保留 port 80 的驗證路徑；DNS-01 要長期保留有效且最小權限的 DNS token。不要只測試第一次簽發。

用 HTTP-01 申請憑證

  1. 完成 DNS 與轉送

    讓該網域解析到你的公開 IP，並只把路由器 TCP 80、443 轉送至 NPM 所在主機。不要轉送 TCP 81。

  2. 先建立可用的 Proxy Host

    在 Hosts → Proxy Hosts 建立與憑證網域完全相同的主機，先確認外部可用 HTTP 到達。NPM 官方憑證說明指出，HTTP 驗證需要可由 HTTP 存取且指向這台 Nginx 的 Proxy Host。

  3. 在 SSL 分頁申請

    編輯該 Proxy Host，在 SSL 分頁選擇申請新的 Let's Encrypt 憑證，填入有效 email、同意服務條款，且不要勾選 DNS Challenge。

  4. 儲存並以外部網路驗證

    從行動網路測試，確認憑證主體涵蓋該網域。測試結果或錯誤記錄若要分享，先遮蔽網域、IP、憑證資訊與完整 log。

不要關掉 port 80 就當作加固：採 HTTP-01 時，NPM 官方說明要求 Proxy Host 繼續可由 HTTP 存取，才能續期。若不能接受，改用 DNS-01。

用 Cloudflare DNS-01 申請憑證

  1. 建立專用 API token

    在 Cloudflare 建立只供 Certbot 使用的 token，只授權目標 zone 的 DNS 編輯；不要使用權限過大的 Global API Key。Certbot Cloudflare 外掛官方也建議使用可限制到特定網域的 API Token。

  2. 選擇 DNS Challenge

    在 Proxy Host 的 SSL 分頁申請 Let's Encrypt 憑證，勾選 Use a DNS Challenge，DNS Provider 選 Cloudflare。

  3. 填入 token 格式

    在 Credentials File Content 使用 Cloudflare 外掛支援的 token 欄位；以下只是假值，不可換成真 token 後截圖或提交到 Git：

    dns_cloudflare_api_token = <只限目標 zone 的 DNS token>

  4. 等待 DNS 傳播後儲存

    使用預設傳播等待值開始；只有確定 TXT 記錄尚未傳播時才逐步增加。申請完成後，不要刪除 NPM 所需的 token，否則自動續期會失敗。

token 是機密：不要放進瀏覽器書籤、教學截圖、聊天記錄、Git 或工單。若懷疑外洩，立即在 DNS 供應商撤銷並建立新的最小權限 token，再更新 NPM。

套用憑證與 Force SSL

  1. 選取正確憑證

    編輯 Proxy Host，在 SSL Certificate 選擇涵蓋該完整網域的憑證。不要以為一張未包含主機名稱的憑證也能通用。

  2. 先測試 HTTPS

    儲存後直接開啟 https://<你的網域>，確認上游服務正常、憑證鏈有效且沒有重新導向迴圈。

  3. 再啟用 Force SSL

    確認 HTTPS 無誤後勾選 Force SSL。NPM 的上游範本會在已有憑證時載入強制 HTTPS 設定。

  4. 測試 HTTP 入口

    開啟 http://<你的網域>，確認會導向相同主機的 HTTPS，而不是錯誤網域或無限迴圈。

Cloudflare Tunnel 例外：若 Tunnel 的內部 Service URL 是 NPM 的 http://…:80，不要在 NPM 啟用 Force SSL，否則 Cloudflare 每次以 HTTP 回源時可能反覆收到 HTTPS 重新導向。請在 Cloudflare 邊緣處理 HTTP 轉 HTTPS；第 8 章會完整說明。

HSTS 要最後才開

HSTS 透過 Strict-Transport-Security 告訴瀏覽器，未來只能以 HTTPS 存取。NPM 上游範本只有在已選憑證、Force SSL 與 HSTS 都啟用時才加入標頭，預設有效時間為兩年。

  1. 先確認 HTTPS 長期可用

    確認憑證涵蓋正確網域、續期路徑可用、所有必要內容都支援 HTTPS，再啟用 HSTS。

  2. 先不要勾 Include Subdomains

    若任何子網域尚未支援 HTTPS，includeSubDomains 會讓它也被瀏覽器強制升級而無法使用。先逐一盤點所有子網域。

  3. 從測試用主機開始

    先在非關鍵子網域測試瀏覽器、API 與行動 App，再決定是否套用到正式服務。

HSTS 不適合試按：瀏覽器會記住政策直到 max-age 到期；關掉 NPM 選項不代表使用者瀏覽器立即忘記。只有在 HTTPS 與續期都可靠時才啟用，對 Include Subdomains 更要保守。

確認自動續期真的可用

  1. 在 Certificates 檢查到期日

    記錄憑證涵蓋範圍與到期日，但不要把真實網域或憑證內容放入公開文件。NPM 上游程式會定期檢查 Let's Encrypt 憑證並處理即將到期者。

  2. 保留原驗證條件

    HTTP-01 保留 DNS 指向及公網 port 80；DNS-01 保留有效、最小權限的 DNS token。Token 輪替後要同步更新 NPM。

  3. 定期檢查失敗訊息

    只在可信任管理面查看 add-on 與憑證記錄。分享排錯資料前遮蔽網域、公開／私有 IP、token、憑證、帳號與完整 log。

  4. 在到期前安排人工複查

    自動化不是免維護。DNS 供應商權限、路由器規則或網域續費異動，都可能讓下一次續期失敗。

常見問題與處理

具體問題先檢查安全處理
HTTP-01 顯示 timeout 或連線失敗公網 DNS、CGNAT、ISP 是否封鎖 port 80、路由器 TCP 80 是否到 NPM不要改開 port 81；無法提供 port 80 時改用 DNS-01
HTTP-01 回傳錯誤內容或 404網域是否落到另一台主機、Cloudflare Proxy 或舊轉送規則逐層核對 Host 與入口，不要公開完整設定檔或 log
DNS-01 無法建立 TXT 記錄token 是否有目標 zone 的 DNS 編輯權限、憑證欄位格式是否正確不要為了方便改用 Global API Key；重新建立最小權限 token
DNS-01 等不到驗證記錄權威 DNS 是否已出現 _acme-challenge TXT、傳播等待是否太短先查權威 DNS，再小幅增加等待時間，避免連續重試觸發速率限制
開啟 Force SSL 後重新導向迴圈Cloudflare SSL／Tunnel 回源協定、上游應用自身的 HTTPS 轉向先關閉其中重複的一層；Tunnel HTTP 回源時由 Cloudflare 邊緣轉向
啟用 HSTS 後測試站打不開瀏覽器是否已記住 HSTS、子網域是否不支援 HTTPS修復 HTTPS，而不是引導使用者忽略憑證警告；評估影響後再調整政策

SSL 常見問題

HTTP-01 成功後可以關閉 port 80 嗎？
不建議。NPM 官方憑證說明指出，HTTP 驗證的 Proxy Host 仍須提供 HTTP 存取才能續期。若你不想公開 port 80，改用 DNS-01。
萬用字元憑證可以用 HTTP-01 嗎？
不行。Let's Encrypt 官方明確說明 HTTP-01 不支援萬用字元；請使用 DNS-01。
Force SSL 和 HSTS 是同一件事嗎？
不是。Force SSL 由伺服器把 HTTP 請求重新導向 HTTPS；HSTS 是瀏覽器記住未來只能使用 HTTPS 的政策。
Cloudflare Tunnel 還需要 NPM 的公有憑證嗎？
若 Tunnel 以 HTTP 連到隔離內網中的 NPM port 80，瀏覽器看到的是 Cloudflare 邊緣憑證，NPM 不一定需要公有憑證。若改以 HTTPS 回源，則要另外正確驗證回源憑證。
可以把 DNS token 貼到工單請人代查嗎？
不可以。Token、憑證、網域、IP 與完整 log 都是敏感資料。請撤銷任何已外洩 token，只提供已遮罩的錯誤摘要。
