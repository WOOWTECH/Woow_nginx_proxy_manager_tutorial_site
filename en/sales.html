讓每個內部服務，都有好記又安全的網址

Nginx Proxy Manager（NPM）把 Nginx 常見的反向代理與憑證設定做成網頁介面。你不必為每個服務背連接埠，也能集中管理網域、HTTPS 與基本存取限制。

自訂網域網址取代 IP 與連接埠
HTTPS集中申請與更新憑證
Access List加上一層入口限制

為什麼你會需要 NPM

Home Assistant、NAS、相簿、影音或內部工具，往往各有一組 IP 與連接埠。直接把服務逐一暴露到網際網路，不只難記，也會增加設定疏漏與攻擊面。

NPM 讓網路請求先到同一個入口，再依網域名稱轉送到正確服務。例如 home.example.com 指向 Home Assistant，photos.example.com 指向相簿服務。後端位址改變時，你只需更新代理設定。

一句話說明：NPM 像服務入口的接待台；你給訪客一個清楚的網址，它負責把連線安全地帶到正確服務。

四項核心價值

能力你得到的價值界線
友善反向代理用表單建立 Proxy Host，集中查看轉送目標與常用選項。進階標頭、WebSocket 或特殊協定仍需理解後端需求並測試。
自訂網域以容易記憶的網域取代 IP 與連接埠，後端搬遷不影響使用者網址。NPM 不是 DNS 代管服務；你仍要在 DNS 供應商建立紀錄。
HTTPS 憑證可透過 Let's Encrypt 申請憑證，也可匯入自有憑證，並指派給主機。自動簽發需要正確 DNS、公開驗證路徑或支援的 DNS Challenge 設定。
存取控制Access List 可依來源位址規則或 HTTP 基本驗證限制入口。它不是完整身分治理或單一登入平台；高敏感服務應使用應用程式本身的 MFA 與權限。

一條連線怎麼走

  1. DNS 找到入口

    你在 DNS 供應商把服務網域指向家中固定 IP、代管主機，或依 Tunnel 架構交給 Cloudflare。

  2. TLS 建立 HTTPS

    瀏覽器檢查網域憑證；NPM 終止 TLS 時，會使用你為該 Proxy Host 指派的憑證。

  3. NPM 判斷主機名稱

    NPM 依網域套用 Proxy Host、Access List 與相關設定，再轉送到後端服務。

  4. 後端仍要自我防護

    應用程式繼續負責帳號、MFA、授權、修補與資料保護，不能只依賴代理入口。

HAOS 上的架設方式

如果你已使用 Home Assistant OS（HAOS），可評估社群維護的 Nginx Proxy Manager add-on。一般流程是先備份 HAOS，加入可信的 add-on 來源，安裝後設定持久儲存與連接埠，再登入 NPM 建立 Proxy Host。

先確認再安裝：社群 add-on 並非 NPM 或 Home Assistant Core 的官方元件。來源、維護狀態、支援架構與設定鍵可能改變，請以你選用版本的說明文件為準。
  • 對外直連通常需要路由器把 TCP 80/443 導向 NPM，並確認電信商未使用 CGNAT。
  • 若只在區域網路使用，可搭配內部 DNS，不必把服務公開到網際網路。
  • 同一台 HA 主機同時承擔自動化與代理服務，管理方便，但也形成共同故障點；更新前要有可還原備份。

自架、代管與 Cloudflare Tunnel

方案適合你在意的事主要代價
HAOS 自架 NPM現有主機就近管理，區網後端不必搬家，資料路徑由你規劃。你要處理路由器、防火牆、更新、備份、電力與固定 IP 或動態 DNS。
受管／雲端 NPM需要較穩定的公開入口，希望由服務商維護主機與監控。有持續費用；雲端 NPM 到家中後端仍需安全通道，並要釐清資料、金鑰、備份與退出機制。
Cloudflare Tunnel 搭配 NPM無法或不想開 inbound 80/443，希望由 outbound tunnel 發布服務。流量與 TLS 架構會依賴 Cloudflare；需避免 Tunnel 規則繞過原本預期的 NPM Access List。

Cloudflare Tunnel 可以把公開主機名稱直接送到後端，也可以送到 NPM；兩種拓撲的 TLS 終止點、真實來源 IP、Access List 行為與日誌位置不同。採用前先畫出資料流並做存取測試，不要假設把兩套工具接起來就會自動更安全。

誠實看待安全取捨

反向代理不是安全保證。它可減少直接暴露後端連接埠並集中 TLS，但 NPM 本身也成為高價值入口。管理介面不應直接公開，且必須定期更新。
  • 帳號：初次登入立即更換預設憑證，為管理者使用唯一長密碼；NPM 版本若支援更強驗證，依官方文件啟用。
  • 最小暴露：不需公開的服務留在區網或 VPN；只發布必要網域與連接埠。
  • 雙層授權：Access List 適合入口篩選，但應用程式本身仍要啟用 MFA、角色權限與登入稽核。
  • 來源 IP：使用 CDN、Tunnel 或上游代理時，只有在可信代理鏈正確設定後才能採信轉送標頭。
  • 備份：備份設定、資料庫與憑證私鑰，應加密、限制讀取並實際演練還原。
  • 可用性：單一 NPM 故障會影響所有入口；重要情境需準備監控、復原時間與替代連線方式。

先用需求選方案

你的情境建議起點
只想在家中用好記網址HAOS 或其他主機自架 NPM，加上內部 DNS，不對外開放。
有固定公開 IP，也願意維運自架 NPM；只轉送 80/443，強化管理入口與後端帳號。
位於 CGNAT 或不想開入站連接埠評估 Cloudflare Tunnel，先釐清信任邊界、TLS 與來源 IP。
需要服務等級、監控與代維護比較受管方案的 SLA、備份、事件回應、資料位置與退出程序。

常見問題

NPM 會幫我管理 DNS 嗎？
不會。你仍要在 Cloudflare 或其他 DNS 供應商建立 A、AAAA、CNAME 等紀錄；NPM 負責收到請求後的代理與憑證設定。
有 HTTPS 就能放心公開服務嗎？
不夠。HTTPS 保護傳輸，不能修補弱密碼、過期軟體或錯誤授權。公開前仍要做更新、MFA、最小權限與備份。
Cloudflare Tunnel 一定比開連接埠安全嗎？
它能移除直接入站連接埠，但同時增加第三方依賴與設定層。安全性取決於 Tunnel 路由、Cloudflare Access、NPM 與後端是否一致實施最小權限。
NPM 適合企業單一登入嗎？
NPM 的 Access List 不是完整的企業身分平台。需要 SSO、條件式存取或完整稽核時，應另行評估專用身分代理。

從一個低風險服務開始

先盤點網域、DNS、後端位址與公開需求，再用測試網域完成第一個 Proxy Host。確認 HTTPS、登入、來源 IP、備份與還原都符合預期後，才逐步移轉其他服務。
