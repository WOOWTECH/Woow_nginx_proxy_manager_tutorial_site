Chapter 4

管理介面與核心物件

先看懂 Dashboard、Hosts、憑證、存取清單與使用者之間的關係，再開始建立第一條反向代理規則。

Dashboard 能看什麼

登入後的 Dashboard 是主機物件摘要，不是流量監控儀表板。Woow add-on 目前採用的 Nginx Proxy Manager 2.12.4 介面，會依你的權限顯示 Proxy Hosts、Redirection Hosts、Streams 與 404 Hosts 的數量卡片；按卡片可進入相應清單。

先做安全確認：若你仍能用 admin@example.com／changeme 登入，請立即更改 email 與密碼。管理介面的 81/tcp 只能留在可信任的區域網路或受保護的管理通道，不可直接公開到網際網路。

核心物件地圖

NPM 把不同目的的設定拆成物件。建立前先選對類型，日後排錯會容易許多。

物件用途典型輸入是否處理 HTTP
Proxy Host依網域把要求轉送到內部 Web 服務網域、上游協定、主機、連接埠是
Redirection Host把來訪者導向另一個 URL來源網域、目的 URL、狀態碼是，回傳重導向
404 Host讓指定網域回傳找不到頁面網域是，回傳 404
Stream轉送 TCP 或 UDP 連線進入連接埠、目標主機與連接埠否
SSL Certificate保存 Let's Encrypt 或自訂憑證，供 Host 引用網域、驗證方式或憑證檔支援 HTTPS
Access List以 HTTP 基本驗證或 IP 規則限制 Proxy Host帳號規則、允許／拒絕來源套用於 Proxy Host

Hosts 選單怎麼分

Proxy Hosts 是本教學最常使用的物件：同一組 80／443 入口可依請求中的網域，分流到不同內部服務。Redirection Hosts 只負責把瀏覽器帶往別處；404 Hosts 用來明確拒絕某個名稱；Streams 則處理非 HTTP 的 TCP／UDP 流量。

清單中的 Enabled／Disabled 是該物件是否生效，不代表上游服務一定健康。Dashboard 的數量也不能取代實際連線測試。

憑證與 Access Lists

SSL Certificates 與 Access Lists 都是可重複引用的物件。一張涵蓋正確名稱的憑證可以指派給 Proxy Host；一份 Access List 也可套用到多個 Proxy Host。修改共用物件前，先確認有哪些服務會受影響。

敏感資料：網域、憑證與私鑰、DNS API token、Access List 密碼都不得貼到公開 issue、截圖或未遮罩的文件。DNS Challenge 憑證資料屬高權限機密，應採最小權限並限制可操作的 DNS zone。

Users 與 Audit Log

Users 管理可登入 NPM 的人員與權限；它和 Access List 不同，後者保護的是被代理的網站。官方功能清單也列出使用者管理、權限與 Audit Log。日常操作應使用個別帳號，避免多人共用管理員密碼。

Audit Log 用來回查管理操作，不等於 Nginx 的存取或錯誤記錄。匯出或分享任何記錄前，先遮罩帳號、網域、公私有 IP、憑證資訊、要求路徑與完整 log。

安全導覽步驟

  1. 確認管理入口

    從區域網路開啟 Home Assistant 的 add-on Web UI，或使用受保護的管理通道。檢查路由器沒有把外部連接埠 81 轉送到 NPM。

  2. 確認個人帳號

    從右上角個人選單確認 email 已不是預設值，密碼也已更換為唯一且足夠長的密碼。

  3. 依序打開清單

    只瀏覽 Hosts、SSL Certificates、Access Lists、Users 與 Audit Log，不新增、刪除或停用既有物件。

  4. 記下相依關係

    對預計調整的 Proxy Host，記錄它引用的憑證與 Access List 名稱；筆記中以代號取代真實網域、IP 與帳號。

物件建立順序

第一次建置可依「確認上游服務 → 建立 DNS → 建立 Proxy Host → 從內外網測試 → 申請並指派憑證 → 視需要套用 Access List」進行。DNS 和 Proxy Host 必須使用相同的完整網域名稱，NPM 才能依 Host header 選到正確規則。

憑證、存取規則與 Proxy Host 是分開保存的物件；刪除任何共用項目前，先檢查引用關係並保留可還原的備份。

管理面安全邊界

  • 對外服務入口通常是 80／443；81 是管理埠，路由器與雲端防火牆都不可公開它。
  • 不要把 NPM 管理頁本身當作第一個公開的 Proxy Host；若要遠端管理，優先使用 VPN 或具身分驗證的管理通道。
  • 共享畫面或求助時，遮罩所有真實網域、公私有 IP、密碼、token、憑證內容與記錄。
  • Advanced 欄位會直接影響 Nginx 行為；沒有依據時保持空白，不貼入來源不明的設定片段。

介面排錯

具體問題先檢查安全處理
Dashboard 數量顯示「-」或一直載入重新整理後確認 add-on 仍在執行，並檢查瀏覽器是否阻擋 API 要求只擷取錯誤類型；不要公開完整瀏覽器回應或 token
看不到 Users、Streams 或部分 Hosts確認目前帳號的角色與檢視／管理權限由既有管理員調整最小必要權限，不共用管理員帳密
Host 顯示 Disabled確認是否由維護者刻意停用，並查 Audit Log不確定影響範圍時不要直接啟用或刪除
開啟 Web UI 出現無法連線確認 add-on 已啟動、81 沒被其他服務占用，並從同一區域網路測試不要為了排錯把 81 暫時轉送到網際網路
儲存表單後出現 Internal Error檢查必填欄位、輸入格式與 add-on 記錄中的同一時間點分享前只保留必要片段並遮罩網域、IP、憑證與完整 log

常見問題

Dashboard 的數字能證明代理正常嗎？
不能。數字是物件數量摘要；你仍要實際解析網域並用瀏覽器或 curl 測試回應。
Access List 帳號能登入 NPM 嗎？
不能把兩者視為同一種帳號。Users 是管理介面使用者；Access List 的 HTTP 基本驗證保護特定 Proxy Host。
可以公開 81 再用強密碼保護嗎？
不建議，也不符合本教學安全邊界。81 不可直接暴露到網際網路；請改從可信任區域網路、VPN 或受保護的管理通道進入。
可以先刪掉不認識的 Host 嗎？
不可以。先查清建立者、引用的憑證與用途，做好備份；不確定時保持原狀。
為什麼畫面和官方最新截圖不同？
Woow add-on 的 README 與 config 目前標示上游 NPM 2.12.4，而官方專案仍持續更新。欄位名稱或版面可能不同，請以你所安裝版本與上游文件為準。
