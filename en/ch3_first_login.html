Chapter 3

First login and account security

Your first login has one priority: retire the publicly known default email and password right away, then verify that the new credentials really work.

Close the admin surface before you log in

The WOOWTECH README lists the initial login details as admin@example.com / changeme and requires you to change them as soon as you log in. The upstream NPM 2.12.4 setup routine creates the first administrator with the same pair; they are public information, not secrets.

  • Confirm you are connecting from a trusted LAN, not over mobile data or public Wi-Fi.
  • Confirm the router has no WAN port forwarding for TCP 81, and that no firewall rule lets an arbitrary internet source reach 81.
  • Close screen recorders, live streams and anything that syncs form contents; treat the password, the email address, IPs and the login screen as sensitive data.
  • Have a trusted password manager ready, but do not paste the new password into a chat, an issue, a screenshot or ordinary notes.
Close it first, then log in. If TCP 81 is already public, do not carry the risk on a promise to "change the password in a minute"; remove the public entry point before you continue with this chapter.

Log in once with the defaults

  1. Open the right Web UI

    From the Home Assistant add-on page choose "OPEN WEB UI", or open http://<HA區網位址>:81 from a trusted LAN. Check that the address is your own NPM; do not reach the login page from a search result.

  2. Enter the initial email

    Enter admin@example.com. Use this value for the initial hardening only; do not keep it as your day-to-day login identity.

  3. Enter the initial password

    Enter changeme and log in. Do not let the browser save this default as a real password.

  4. Go straight to the account settings

    Once you are in, do not start by creating a Proxy Host, a certificate or another user; finish the account details and password change in the next sections first.

Use it once only: if the default credentials do not work, do not keep guessing and do not reset the database; first check whether an administrator has already completed the initial setup.

Change the email immediately

  1. Open Users

    In the NPM main menu, open Users and find the current Administrator account.

  2. Edit the details

    Open the account's action menu and choose Edit Details (a localized interface may show a translated label).

  3. Replace the default email

    Change admin@example.com to a login email you control and do not share with anyone else, and check that the name and nickname do not give away anything unnecessary. An email address is sensitive data too; keep it out of screenshots.

  4. Save, then change the password

    Click Save. The NPM 2.12.4 interface used by the add-on does not allow you to keep the default email; once you save new details on the default account, the password dialog opens next.

If a later interface revision changes the flow, the principle does not: change the default email in the current administrator's details first, then use Change Password on the same account. Do not create a second administrator to work around the hardening.

Set a new password immediately

  1. Confirm you are editing your own account

    The password dialog should show the current administrator. If it does not, cancel and go back to Users to pick the right account.

  2. Enter the current password

    During the initial hardening, the current password is the default you used a moment ago. The interface asks for Current Password whenever you change your own password.

  3. Generate a unique new password

    Use a password manager to generate a long, random password you have not used on any other site. The NPM 2.12.4 frontend field has a minimum length of 8 characters, but a minimum is not a security recommendation.

  4. Confirm and save

    Enter the same new value in New Password and Confirm Password, then save. Keep the new password in a trusted password manager only; do not copy it into a public or synced document.

Change both the email and the password: changing one of them is not enough. The end state must no longer use admin@example.com and must no longer accept changeme.

Log out and verify

  1. Log out deliberately

    Once you have saved, use NPM's log out function; do not only close the tab.

  2. Log in with the new credentials

    Open the same trusted-LAN Web UI again and fill in the new email and the new password from your password manager.

  3. Confirm the account identity

    Go back to Users and confirm that the current administrator shows the new email and that the admin functions still work. Do not capture a screen that contains real data.

  4. Confirm the defaults no longer work

    In a private browsing window, test the old default pair once against the correct LAN address; it should fail to log in. Avoid repeated retries; one attempt is enough to confirm it.

The passing condition is "new credentials succeed, default credentials fail". Verifying only that the new credentials work still does not prove the default password is retired.

Keep the admin boundary

ItemSafe practiceUnsafe practice
TCP 81Reachable only from a trusted LAN or a controlled management channelRouter WAN port forwarding, any-source firewall rules
Login emailA non-default identity you control, held in a trusted vaultKeeping admin@example.com, or letting it appear in a public screenshot
Admin passwordLong, random, unique, held in a password managerReused, shared, or written into a Proxy Host config or ordinary notes
SessionLog out on a shared device as soon as you are done; keep the admin device updatedSaving the login on a public computer, or leaving a device unlocked for long stretches
Help requestsPost only the error text you need, redactedUploading full logs, certificates, tokens, domains, or public and private IPs

Changing the password does not turn the admin interface into something fit to publish. TCP 81 must still never be exposed to the public internet, and later chapters will not wrap it in a public Proxy Host either.

Keep a safe admin record

You can keep an operations record that holds no secrets, for example "the default account was retired on this date", "the admin surface is limited to the trusted network segment", "the date of the next permissions review". Do not write a real email address, password, full domain or IP into that record.

  • Password and login email: in a protected password manager entry only.
  • DNS API token: if you use a DNS Challenge later, store it separately and give it least privilege.
  • Certificates and private keys: leave them to NPM and your backup mechanism; do not paste them into an issue.
  • Logs: quote only the few lines directly related to the error, and redact domains, public and private IPs, accounts, tokens and certificate contents first.
Mark it done: you can record "login with the new credentials succeeded, the default pair failed, 81 has no WAN entry point", but do not record the new credentials themselves.

Login and hardening troubleshooting

Problem 1: the default credentials do not work

First confirm that the address is your own NPM on TCP 81, and that capitalization and your input method are correct. If this instance has been used before, an administrator may already exist; do not delete the database in order to get the defaults back.

Problem 2: saving is rejected for admin@example.com

This is the expected protection in NPM 2.12.4: the default email is not allowed to stay. Change it to a non-default login email you control, then save.

Problem 3: the new password and the confirmation do not match

Clear both fields and refill them from the password manager with the same generated value. Do not switch to a short or reused password for convenience.

Problem 4: Current Password comes back as invalid

Confirm that the account you are editing is your own, and enter the password that is still valid. If the email change went through but the password dialog was interrupted, go back to that account in Users and choose Change Password.

Problem 5: the new credentials still do not work after the change

Stop retrying first, check whether the new email was saved and whether the password manager entry was updated, then try again from the trusted LAN. Do not post the form or a full log in a public channel.

Problem 6: 81 turns out to open from outside your network

That is not a convenience feature, it is exposure. Remove the router's WAN port forwarding and any over-broad firewall rule first, then check whether a public DNS entry or a proxy path still leads there.

FAQ

Can I change only the password and keep the default email?
No. The task is to retire the publicly known default login identity and the default password together; the NPM 2.12.4 account form does not allow you to keep admin@example.com either.
Is a password of at least 8 characters enough?
8 characters is the minimum enforced by that version's frontend field, not a security target. Use a password manager to generate a longer, random and unique password.
Once I have a strong password, can I expose TCP 81?
No. A strong password does not remove the risk of vulnerabilities in the admin interface, brute-force attempts and misconfiguration; 81 stays limited to a trusted LAN or a controlled management channel.
If I forget the new password, can I delete the database and start over?
Do not. Deleting the database can also lose your Proxy Hosts, users and other settings. Preserve the current state and a backup first, then read the official support material for the matching version before you begin any recovery procedure.

If the add-on has since been updated or the interface differs, the security requirement still holds — change the email and password immediately, and keep 81 off the public internet — and go by the official docs for your version.
