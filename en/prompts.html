WoowTech · Nginx Proxy Manager Prompt Library

Manage NPM safely, one clear sentence at a time

Hand the 45 prompts below to an AI Agent, or use them as your own operations checklist. Every one of them requires the agent to identify the environment and the evidence first; anything that deletes, disables, overwrites or restores has to preview the impact and wait for your explicit confirmation.

Agree on tools and safety limits first

Nginx Proxy Manager has an interface that its own front end uses, but it can change between versions, so you must not treat an unverified path, field or permission as a stable public API. These prompts name no API endpoint. If the agent wants to use the API, it has to identify your NPM version first and verify the method, path, fields and response against that version's official source code or a schema that is actually available; where it cannot verify, it must give web interface steps only, and must not guess or send a request.

Paste this at the start of every conversation: "Read-only by default. Redact passwords, tokens, cookies and private keys. State your data source first; before any write, give me the before-and-after diff, what it affects and the rollback plan, and act only after I explicitly type 'confirm'. Answer in English."
A note on permissions: Restrict the agent's account to the least privilege the task needs, and never paste an admin cookie or password into the conversation. Back up production first, then verify the automation on a test host.

Proxy Hosts (10 prompts)

1. Host inventory
Take a read-only inventory of every Proxy Host on this NPM, listing the domain, the Forward Scheme, the Forward Hostname / IP, the Forward Port, the assigned certificate and the Access List; redact sensitive information and state how you obtained the data. Answer in English.
2. Plan before you create
I want to proxy "app.example.com" to "192.0.2.20:8080" on the LAN. Check DNS, backend reachability, the WebSocket requirement and where TLS terminates first, then draft the values for the NPM form; do not create any configuration. Answer in English.
3. Create a Proxy Host
Create a Proxy Host from the domain and backend I give you. Show the full preview, the conflict check and the rollback plan first; only after I type "confirm" may you create it through a method you have verified for this version, otherwise give web interface steps only. Answer in English.
4. Change the forward target
Prepare to move the backend of "app.example.com" from the old address to the new one. Test the health of the new backend first, then list the current values, the intended values, the affected domains and the rollback values; change nothing until I confirm. Answer in English.
5. WebSocket troubleshooting
Normal pages on "app.example.com" load fine, but its real-time features are broken. Inspect the NPM Proxy Host, the backend documentation and the browser errors read-only, and decide whether WebSocket support is needed; propose the smallest change and do not apply it. Answer in English.
6. Custom config audit
Read-only: check the Advanced custom Nginx config on every Proxy Host and find snippets that are duplicated, that conflict with each other, or that could override a security header or the source IP; quote the actual content and suggest improvements, but change no files. Answer in English.
7. Unencrypted backend inventory
Take stock of the Proxy Hosts where NPM connects to the backend over HTTP. Classify the risk as "same host", "trusted LAN" or "across an untrusted network", then recommend backend TLS or network isolation; do not assume HTTP is always unsafe or always acceptable. Answer in English.
8. Domain conflict check
Read-only: check whether Proxy Hosts, Redirection Hosts and other entry points reuse the same domain, and list the entries that could confuse routing along with the evidence; delete or disable nothing. Answer in English.
9. Disable a host
I want to pause "old.example.com". First list its DNS, certificate, Access List, backend and dependencies, and explain what breaks once it is disabled and how to re-enable it; disable it only after I type "confirm". Answer in English.
10. Delete a host
I want to delete "old.example.com". First confirm it is not a production entry point that still carries traffic, then show a complete backup of its configuration, the resources that depend on it, what it affects and the rollback plan; delete it only after I type "delete old.example.com". Answer in English.

DNS and certificates (10 prompts)

11. DNS resolution check
Query the public A, AAAA and CNAME results for "app.example.com" and compare them with the entry point I expect; explain that DNS is managed by an external provider, and do not invent a DNS editing feature inside NPM. Answer in English.
12. Split DNS plan
I want "app.example.com" to resolve to a LAN address at home and to the public entry point from outside. Plan a split DNS setup and cover caching, the certificate name and how to troubleshoot it; design only for now. Answer in English.
13. Certificate inventory
Read-only: list the certificates NPM manages, with the name, the domains covered, the issuer, the expiry date and which hosts use them; do not output private keys, DNS API tokens or full certificate contents. Answer in English.
14. Expiry risk
Group the certificates that are about to expire into 7-, 14- and 30-day bands, check that their domains still resolve to the correct entry point, and list what has to be in place before renewal; stay read-only throughout. Answer in English.
15. HTTP Challenge preparation
I want to request a Let's Encrypt certificate for "app.example.com". First verify public DNS, TCP 80 reachability, NAT and any conflict with an existing host, then show a preview of the request; do not submit the request before those checks are done. Answer in English.
16. DNS Challenge assessment
My service does not expose TCP 80. First verify whether the NPM version I run supports my DNS provider and the fields it needs, then explain the least privilege the token needs and how to store the secret; do not guess a provider name and do not create a token. Answer in English.
17. Assign an existing certificate
Prepare to assign an existing certificate that covers "app.example.com" to that Proxy Host. Check the SAN, the validity period and the current TLS settings first, and show the differences; change nothing until I confirm. Answer in English.
18. Force HTTPS redirect
Assess whether Force SSL is a good fit for "app.example.com". Confirm first that HTTPS already works, that the backend will not create a redirect loop and that webhooks are unaffected, then list a test plan; turn it on only after I confirm. Answer in English.
19. Certificate error diagnosis
The browser reports a certificate name mismatch for "app.example.com". Collect the certificate chain that is actually served, the SNI, the DNS records and the NPM host mapping, then point to the evidence and the most likely cause; do not reissue the certificate first. Answer in English.
20. Remove a certificate
I want to remove an old certificate. First list every Proxy Host and Redirection Host that references it, back up the metadata that matters and confirm the replacement certificate; remove it only after I type a confirmation sentence containing the certificate name. Answer in English.

Access Lists and users (8 prompts)

21. Access List inventory
Take a read-only inventory of every Access List, covering its allow/deny source rules, whether it uses HTTP Basic Authentication and which hosts it is applied to; always redact user passwords. Answer in English.
22. Over-broad rule audit
Check the Access Lists for over-broad network ranges, questionable rule order and lists that no host uses. Quote the actual rules and explain the risk; do not tighten anything on your own. Answer in English.
23. Draft a new list
I want "admin.example.com" to accept only my home static IP and the VPN range. Draft an Access List, and first verify the CIDRs, the fallback login path and the risk of locking myself out; do not create it. Answer in English.
24. Apply a list
Prepare to apply the "trusted-only" Access List to "admin.example.com". First list the current settings, how the rules evaluate, the risk to remote administration and the rollback steps; apply it only after I confirm. Answer in English.
25. Basic Auth account rotation
Plan a rotation of the HTTP Basic Authentication accounts on one Access List. Take stock of the affected hosts first and produce a cutover order that causes no interruption; handle passwords only through an approved secret channel, and make no change until I confirm. Answer in English.
26. NPM user inventory
Take a read-only inventory of the users who can log in to the NPM admin interface, their roles and whether they are enabled, and find shared accounts and accounts nobody needs any more; do not show credentials, and do not confuse Access List accounts with admin users. Answer in English.
27. Least-privilege check
Compare what each NPM user actually does with the permissions they hold, and draft a least-privilege adjustment. First explain the role capabilities the current version offers and where you verified them; do not assume fine-grained permissions that do not exist. Answer in English.
28. Delete a user or a list
I want to delete an NPM user or an Access List. First list the resources it owns, what references it, its last known use, what it affects and the alternatives; act only after I type a "confirm delete" that contains the exact name. Answer in English.

Redirection Hosts and Streams (8 prompts)

29. Redirection inventory
Read-only: list every Redirection Host with its source domain, target URL, redirect status code, path preservation setting and certificate, and find any potential loop or stale target. Answer in English.
30. Create a permanent redirect
I want to redirect an old domain to a new one. First compare what 301 and 302 do to caching and search indexing, test the target and show a preview of the NPM settings; create it only after I confirm. Answer in English.
31. Redirect loop diagnosis
A request to "old.example.com" fails with too many redirects. Trace the status code and Location of every hop read-only, check the HTTPS rules on the CDN, on NPM and on the backend, and find the first point of the loop. Answer in English.
32. Remove a redirect
I want to remove a Redirection Host. First record its full configuration, look for evidence of recent use and explain the DNS and certificate impact; remove it only after I type a confirmation sentence containing the source domain. Answer in English.
33. Stream inventory
Take a read-only inventory of the NPM Streams, covering the Incoming Port, the Forwarding Host, the Forwarding Port, the TCP/UDP choice and any port conflict; do not run connection scans beyond what I have authorized. Answer in English.
34. Plan a new Stream
I want to forward a non-HTTP service. First confirm whether the protocol is TCP, UDP or both, along with the source restrictions, the firewall and the backend timeout requirements, then draft the Stream settings; do not create it or open the firewall yet. Answer in English.
35. Stream connection diagnosis
One Stream cannot be reached from outside. Work through DNS, the upstream firewall, NAT, what NPM listens on, the TCP/UDP choice and the backend service layer by layer, read-only, and note the evidence at each layer. Answer in English.
36. Disable or delete a Stream
I want to disable or delete a Stream. First list how it is used, the listening port, the backend, the monitoring and the rollback plan; act only after I give an explicit confirmation containing the port and the name. Answer in English.

Backup and diagnostics (9 prompts)

37. Backup scope inventory
Read-only: work out from my NPM deployment option where the configuration, the database, the certificates and the logs live in persistent storage, and produce a backup scope list; do not assume Docker, HAOS and other install methods use the same paths. Answer in English.
38. Build an encrypted backup plan
Design an encrypted backup for this NPM: define the frequency, the retention, the off-site copy, private key access, the integrity check and the failure alert. Output the plan and the test commands first; do not read or upload real secrets. Answer in English.
39. Backup verification
Verify that the most recent NPM backup holds the data I expect, decrypts and matches its checksum. Test only in an isolated scratch area, never overwrite production, and redact the database password and the private keys. Answer in English.
40. Restore drill
Plan a restore of an NPM backup into an isolated environment. First list version compatibility, the downtime needed, DNS isolation, what to verify and the recovery point; run it only after I confirm the test environment, and never overwrite production directly. Answer in English.
41. 502 diagnosis
"app.example.com" is returning 502. Work read-only through the NPM log timestamps, the backend DNS/IP, the port, the protocol, TLS and the backend health, one item at a time, and separate fact from guesswork. Answer in English.
42. 504 diagnosis
"app.example.com" is returning 504. Compare the request duration, the backend response, the network path and the timeout settings; find the root cause before you recommend a change, and do not settle for raising the timeout. Answer in English.
43. Log privacy audit
Sample the NPM access and error logs and check whether they record tokens, cookies, personal data in query strings or internal addresses. Redact sensitive values in your output, and recommend how to minimize, rotate and restrict access to them. Answer in English.
44. Capacity and health
Read-only: check the NPM host for errors relating to CPU, memory, disk, the database and certificate renewal, and build a timeline of the anomalies in the last 24 hours; use only the monitoring and logs that already exist, and install no monitoring agent of your own. Answer in English.
45. Security update plan
Identify the NPM version and deployment option in use and plan an update against the official release information. First list the backup, the compatibility, the maintenance window, the verification and the rollback steps; update only after I explicitly confirm, and never use an unverified image. Answer in English.
