Chapter 2

Install Woow Nginx Proxy Manager

On Home Assistant OS or Supervised, add the WOOWTECH add-on repository, install NPM, and first confirm what TCP 80, 81 and 443 are for and where their boundaries lie.

What this chapter completes

You will install the Home Assistant add-on called Woow Nginx Proxy Manager, start it, and confirm the admin interface works from a trusted LAN only. This chapter sets up no domain, requests no certificate, and does not ask you to open a router port first.

The WOOWTECH repository currently states that this add-on is for Home Assistant OS (HAOS) or Home Assistant Supervised, supports amd64 and aarch64, and needs TCP 80, 81 and 443. If you run Home Assistant Container or Core, these add-on steps do not apply.

Version note: the repository updates the add-on. The version shown on the install page may differ from the config file this chapter was checked against; go by the latest README, changelog and config.yaml you can see.

Take stock before installing

  1. Confirm the installation type

    In Home Assistant's system information, confirm you are on HAOS or Supervised, and that you can open the Add-on Store under Settings.

  2. Confirm the CPU architecture

    Confirm the system is amd64 or aarch64. The WOOWTECH config.yaml currently declares only those two architectures.

  3. Take stock of the ports

    Check whether a service on the same Home Assistant host already uses TCP 80, 81 or 443. Record only what you need, and redact hostnames, private IPs and full logs before you share anything.

  4. Keep what you need to roll back

    Write down the add-ons currently running and their port assignments. If you find a conflict, understand what the existing service is for first; do not disable or delete it outright.

Add the official repository

  1. Open the Add-on Store

    In Home Assistant, open Settings → Add-ons → Add-on Store. Note: a localized Home Assistant interface may label this differently; look for the Add-on Store.

  2. Open the repository list

    Open the menu at the top right, then open Repositories.

  3. Paste the right URL

    Add https://github.com/WOOWTECH/Woow_ha_nginxpm. Check that the owner is WOOWTECH, and do not use a similarly named or archived old repository.

  4. Wait for the list to refresh

    Close the repository dialog, wait for the store to reload, then search for Woow Nginx Proxy Manager.

Note on the old repository: the WOOWTECH README states that the project has migrated away from the old Woow_nginxpm_docker_compose_all and its ha branch; an archived repository no longer receives updates.

Install the add-on

  1. Open the right entry

    Select Woow Nginx Proxy Manager and check once more that the source points at WOOWTECH's Woow_ha_nginxpm.

  2. Read the version information

    Read the README, the changelog, the supported architectures and the permissions, then press INSTALL.

  3. Wait for the install to finish

    How long it takes depends on your hardware and network. Do not press install again or reboot the host because the screen has stopped changing for a moment.

  4. Do not set up WAN forwarding yet

    Stay on the add-on page once the install finishes. At this point no port needs to be exposed to the public internet, and TCP 81 must never be.

The WOOWTECH add-on README states that this add-on needs no extra options; all administration happens in the Web UI on TCP 81.

What 80, 81 and 443 are for

Host portWhat it is forExposure rule
80/tcpThe HTTP reverse proxy entry point; also used for validation when you expose it directly and use HTTP-01Forward it from the WAN only when your design genuinely needs it; do not read a Tunnel or DNS-01 setup as meaning this port must always be open
81/tcpThe NPM admin Web UINever expose it; only a trusted LAN or a controlled management channel is allowed
443/tcpThe HTTPS reverse proxy entry pointA directly exposed design normally forwards it to NPM only; a Tunnel design follows the tunnel layout and leaves no unnecessary extra entry point

The WOOWTECH config.yaml maps 80/tcp, 81/tcp and 443/tcp to ports 80, 81 and 443 on the host; the official NPM Setup page also labels them Public HTTP, Admin Web and Public HTTPS. That describes what each one is for, not that all three ports should be exposed to the WAN.

On the router, WAN entry points only: never create a forward from external 81 → Home Assistant 81. If your router already has that rule, record what it affects first, then safely remove or disable that public entry point.

Start it and check from the LAN

  1. Start the add-on

    On the add-on info page, press START and wait for the status to become running.

  2. Read a short log first

    Check locally only, to see whether startup finished and whether there is a port conflict. A log can contain addresses, domains, certificates or request details, so do not post the whole thing publicly.

  3. Open the Web UI from a trusted LAN

    Use the add-on's OPEN WEB UI button. If the button is unavailable, try http://<HA區網位址>:81 from a trusted LAN; never write your real address into public notes.

  4. Stop at the login page

    Reaching the NPM login screen means this chapter's checks are done. You will use the default credentials in the next chapter, and you must change them immediately after you log in.

The default credentials are not hardened yet: until you finish the next chapter, keep TCP 81 restricted to a trusted LAN, and do not start publishing a Proxy Host.

Your defenses before going public

  • Check the router: there must be no WAN TCP 81 mapped to Home Assistant or NPM.
  • Check the firewall: TCP 81 allows only the trusted management sources you actually need, never an arbitrary source on the public internet.
  • Check DNS: do not create a public record for the admin interface; treat your real domain and both public and private IPs as sensitive data.
  • Check what you share: full add-on logs, certificates, passwords and DNS API tokens must never go into an issue, a chat or a screenshot.
  • Until you have decided between direct exposure and a Tunnel, do not open WAN 80/443 in advance.

For direct exposure, the basic flow in the upstream official guide is to send 80 and 443 to NPM; the WOOWTECH documentation also lists a Tunnel option that needs no router forwarding. Implement whichever one your design calls for, rather than opening every entry point.

Install troubleshooting

Problem 1: the store cannot find Woow Nginx Proxy Manager

Confirm the repository URL is complete and the owner is WOOWTECH, reload the store, and check whether Home Assistant can reach GitHub. Do not add an unvetted mirror instead.

Problem 2: it says this architecture is not supported

Check that the system is amd64 or aarch64. The current config.yaml declares no other architecture; do not force the install with the wrong image.

Problem 3: it fails to start and mentions address already in use

Usually TCP 80, 81 or 443 is already taken. Take stock of the services and add-on ports on the same host; understand what depends on what before you decide which side to change.

Problem 4: the add-on is running but the Web UI will not open

Use OPEN WEB UI first, then check http://<HA區網位址>:81 from the same trusted LAN. Check the local firewall and the VLAN rules; do not use WAN forwarding to work around the problem.

Problem 5: the install never finishes

Check the free storage, the network and the Supervisor log for a specific error. Quote only the lines you need and redact sensitive values; do not paste the whole log.

FAQ

Do I need a domain before I install?
No. You can install it on a trusted LAN and harden the account first, then create a Proxy Host once your architecture and DNS are ready.
Why do I see three ports after installing?
80 and 443 are the entry points for proxied traffic; 81 is the admin interface. The add-on publishes them on the host, which does not mean the router should expose them all.
Can I move host port 81 to another number and expose that?
Changing the number is not a substitute for access control. Whatever the external number is, the admin interface must never be exposed directly to the public internet.
Can I follow this chapter on Home Assistant Container?
No. The WOOWTECH README requires HAOS or Supervised; Container users should plan separately, following the official NPM Docker documentation.
