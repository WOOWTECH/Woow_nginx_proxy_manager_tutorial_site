第 11 章

備份、更新與安全加固

把 NPM 當成網路入口維運：先確認備份真的含有資料庫、設定與憑證，再更新；同時把 port 81 留在可信任管理面，不讓備份與日誌變成另一個敏感資料外洩點。

先定義可復原的維運邊界

Woow Nginx Proxy Manager 是 Home Assistant add-on，不是官方 NPM Docker Compose 的原樣部署。目前 add-on config.yaml 把 addon_config 以可寫方式映射給容器，並只發布 80、81、443。Woow 的 patch 則把上游常見的 /data 狀態路徑改為 /config。

平面內容維運原則
資料平面SQLite、NPM 物件、產生的 Nginx 設定、憑證與金鑰以 HA 備份保護，不手動拆散後假設可還原
管理平面port 81、管理者與權限限可信任網段，不公開到網際網路
流量平面80／443 與明確核准的公開服務只暴露必要入口，upstream 維持私有
稽核平面HA add-on log、NPM audit 資訊最少保留、遮罩後分享，限制可讀者
立即處理預設帳密：Woow README 與 CHANGELOG 都確認 add-on 帶有 admin@example.com／changeme。首次登入後必須立即更改 email 與強密碼；完成前不要建立任何公開入口，更不能公開 port 81。

HA 備份中的 NPM 內容

Woow README 說明 Home Assistant 備份包含所有設定、SSL 憑證與資料庫，而 config.yaml 以 backup_exclude: "*/logs" 排除 log。依目前 add-on 文件，應保護的主要內容如下；實際封裝仍以你建立的備份類型與當下 add-on 版本為準。

內容目前 add-on 路徑敏感性／用途
SQLite 資料庫/config/database.sqliteHost、使用者與 NPM 設定的核心狀態，屬敏感資料
應用金鑰/config/keys.json加密相關金鑰，不得貼到工單或公開倉庫
Nginx 設定/config/nginx/可能揭露網域、私有 IP、port 與路由結構
Let's Encrypt 資料/config/letsencrypt/包含憑證相關檔案與私鑰，必須嚴格保護
自訂憑證/config/custom_ssl/可能包含私鑰，不可透過一般訊息傳送
Access Lists/config/access/包含存取控制資料，不能當作可公開設定
Logs*/logs由 add-on 備份規則排除；部分 Nginx log 已由 Woow patch 導向 add-on 輸出
不要只複製 database.sqlite 就宣稱完成備份。資料庫、金鑰、憑證與產生設定彼此相關；使用 Home Assistant 支援的備份／還原流程，並確認備份已選入 Woow add-on。

更新前建立可用備份

  1. 記錄目前狀態

    在私密維運紀錄寫下 HA 版本、Woow add-on 顯示版本、關鍵 Proxy Host 測試結果與備份時間。不要寫入密碼、DNS API token、憑證私鑰、完整網域或未遮罩 IP。

  2. 到 HA 備份頁建立備份

    前往 Settings／System／Backups 建立手動備份，或確認「更新前備份」已啟用。若使用部分備份，明確選取 Woow Nginx Proxy Manager add-on。

  3. 保存緊急套件

    Home Assistant 官方文件指出備份可加密，還原加密備份需要對應的 encryption key。把 Backup emergency kit 存在 HA 主機以外的安全位置，且註明適用的備份。

  4. 保存異機副本

    不要只把備份留在同一台 HA 儲存裝置。官方建議至少保留一份在另一個系統，理想上再有一份異地副本；兩者都要有存取控制。

  5. 確認完成而非只按下按鈕

    檢查備份工作成功、檔案存在且大小合理，並確認選取內容列出該 add-on。若環境允許，安排隔離的還原演練。

把「可下載」驗證成「可復原」

未演練的備份只能證明曾經產生檔案，不能證明 NPM 能回到可用狀態。正式 HA 上直接還原會覆寫所選部分，請在維護時段或隔離測試設備進行，不要拿生產環境試錯。

  1. 準備隔離環境

    避免還原後的 80／443 與現有 NPM 同時對外，也避免測試 DNS 指向正式服務。

  2. 使用官方 HA 還原流程

    選取對應備份與 Woow add-on，依提示提供 encryption key。不要手動解包後覆寫不完整目錄。

  3. 驗證核心物件

    確認管理者可登入、Proxy／Redirection Hosts、Certificates、Access Lists 與 Streams 數量合理；只用改寫過的盤點資料比對。

  4. 做不對外的服務測試

    確認 add-on 能啟動、Nginx 設定可載入，以及測試 upstream 可代理。測試完成後關閉隔離實例，避免出現兩套入口。

依 add-on 發行節奏更新

目前 Woow config.yaml 宣告版本 2.12.4-v2，addon_info.yaml 對應上游 NPM v2.12.4。上游 NPM 的最新 release 可能更高，但不代表可直接在 add-on 容器內套用 Docker 更新命令。

  1. 讀 Woow CHANGELOG 與發行資訊

    確認是上游 NPM 版本升級，還是相同上游版本的 fork revision，並查看已知限制。

  2. 完成備份與外部測試基線

    保留更新前的 HTTP／HTTPS、憑證與 WebSocket 測試結果，確保出錯時能判斷是更新造成。

  3. 從 Home Assistant 更新 add-on

    使用 HA 提供的 add-on 更新流程，不在容器內執行官方 Docker 文件的 docker compose pull 或替換 image。

  4. 查看啟動 log

    確認資料庫 migration、NPM 後端與 Nginx 都啟動。Woow CHANGELOG 已註明 UI／API 顯示 0.0.0 是既知的外觀問題，不應只靠該數字判斷更新成敗。

  5. 依序驗證與準備回復

    先測管理面與內部 upstream，再測外部 80／443、SSL、重導向及 WebSocket。若出現重大回歸，使用已驗證的 HA 備份回復，不要隨意降級資料庫檔。

port 81 只留在管理面

Woow config.yaml 把 81/tcp 映射為 Admin Web Port，CHANGELOG 更明確指出 80／81／443 會發布在 LAN。這不等於 81 適合從網際網路存取。

  • 路由器只依架構轉送必要的 80／443；任何 WAN → 81 規則都應移除。
  • Cloudflare Tunnel、Proxy Host 或其他公開入口不要指向 http://<HA-private-IP>:81。
  • 在路由器、防火牆或 VLAN ACL 僅允許可信任管理裝置／管理網段連到 HA 的 81。
  • 訪客、IoT 與一般用戶網段不應能連到 81；遠端管理優先使用受控 VPN，而不是公開管理頁。
  • 更改外部映射埠只能降低掃描雜訊，不能取代防火牆、強密碼與最小權限。
port 81 使用 HTTP 管理介面。即使帳密已更換，也不要讓它直接暴露在公網；網域、公開／私有 IP、密碼、DNS API token、憑證與管理 log 全都視為敏感。

管理帳號、token 與憑證

項目最低要求不可做的事
NPM 管理者立即替換預設 email／密碼；每人使用自己的必要權限帳號共用預設帳號或把密碼存進瀏覽器截圖
DNS API token只授予所需 zone 與 DNS 編輯權限，定期輪替使用全域 API key，或貼入公開問題單
憑證與私鑰限制備份、檔案與管理介面的讀取者以 email、聊天室或 Git 傳送私鑰
網域與 IP維運文件限權存放，對外範例全面改寫同時公開網域、公開 IP、私有 IP 與 port 對照
Logs只擷取故障時間附近的必要行並先遮罩上傳完整 add-on log、Authorization、Cookie 或 DNS credentials

刪除使用者、憑證或 Host 會立即影響服務。若你無法確認用途，先盤點擁有者、相依 Host 與最後使用時間；不要用「清理」名義一次刪除未知項目。

具體問題確認方式處理方式

加密備份無法還原確認 emergency kit 與備份建立時間是否相符使用該備份對應的 key；不要輪替 key 後丟掉舊套件

常見問題

只備份 database.sqlite 就夠了嗎？
不夠。Woow 文件列出的狀態還包含 keys、Nginx 設定、Let's Encrypt、自訂憑證與 Access Lists。應使用 HA 支援的 add-on 備份流程。
備份已加密，還需要限制存取嗎？
需要。備份與 emergency kit 應分開、限權且有異機副本；從 HA 頁面下載時，官方文件指出可能會即時解密，下載後的檔案同樣要保護。
可以直接跟著上游 NPM 執行 docker compose pull 嗎？
不可以套用在這個 HA add-on。Woow 有自己的映像、patch、版本與 HA 更新流程，應等待並安裝 Woow 發布的 add-on 更新。
把 port 81 改成別的號碼就安全了嗎？
不是。換埠只能減少一般掃描，管理介面仍須禁止公網存取，並搭配可信任管理網段、強密碼與最小權限。
