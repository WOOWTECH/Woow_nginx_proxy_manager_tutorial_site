第 2 章

安裝 Woow Nginx Proxy Manager

在 Home Assistant OS 或 Supervised 加入 WOOWTECH add-on 倉庫、安裝 NPM，並先確認 TCP 80、81、443 的用途與邊界。

本章完成什麼

你會安裝名為 Woow Nginx Proxy Manager 的 Home Assistant add-on，啟動後只從可信任區網確認管理介面可用。本章不設定網域、不申請憑證，也不要求你先開路由器連接埠。

WOOWTECH 倉庫目前說明此 add-on 適用於 Home Assistant OS（HAOS）或 Home Assistant Supervised，支援 amd64、aarch64，並需要 TCP 80、81、443。若你使用 Home Assistant Container 或 Core，這套 add-on 步驟不適用。

版本提醒：倉庫會更新 add-on。安裝頁顯示的版本可能不同於本章核對時的設定檔；以你看到的最新 README、更新記錄與 config.yaml 為準。

安裝前盤點

  1. 確認安裝類型

    在 Home Assistant 的系統資訊確認是 HAOS 或 Supervised，且你能開啟「設定」中的 add-on 商店。

  2. 確認 CPU 架構

    確認系統為 amd64 或 aarch64。WOOWTECH config.yaml 目前只宣告這兩種架構。

  3. 盤點連接埠

    檢查同一 Home Assistant 主機是否已有服務使用 TCP 80、81、443。只記錄必要資訊，分享時遮罩主機名稱、私有 IP 與完整記錄。

  4. 保留回復資訊

    記下目前運作中的 add-on 與連接埠配置。若發現衝突，先理解既有服務用途，不要直接停用或刪除。

加入官方倉庫

  1. 進入 add-on 商店

    在 Home Assistant 開啟「設定」→「附加元件」→「附加元件商店」。不同版本的繁體中文翻譯可能顯示為「Add-ons」或近似名稱。

  2. 開啟倉庫清單

    選右上角選單，再開啟「Repositories／儲存庫」。

  3. 貼上正確網址

    加入 https://github.com/WOOWTECH/Woow_ha_nginxpm。核對擁有者是 WOOWTECH，不要使用名稱相似或已封存的舊倉庫。

  4. 等待清單更新

    關閉倉庫視窗並等待商店重新整理，搜尋 Woow Nginx Proxy Manager。

舊倉庫提醒：WOOWTECH README 指出專案已從舊的 Woow_nginxpm_docker_compose_all 的 ha 分支遷移；已封存倉庫不再收到更新。

安裝 add-on

  1. 開啟正確項目

    選擇 Woow Nginx Proxy Manager，再次確認來源連到 WOOWTECH 的 Woow_ha_nginxpm。

  2. 閱讀版本資訊

    查看 README、更新記錄、支援架構與權限，再按「INSTALL／安裝」。

  3. 等待安裝完成

    安裝時間依硬體與網路而異。不要因畫面暫時沒有變化就重複按安裝或重開主機。

  4. 先不要設定 WAN 轉送

    安裝完成後留在 add-on 頁面。此時不需要把任何連接埠公開到網際網路，尤其不可公開 TCP 81。

WOOWTECH 的 add-on README 說明此 add-on 不需要額外選項，管理操作都在 TCP 81 的 Web UI 完成。

80、81、443 用途

主機連接埠用途公開原則
80/tcpHTTP 反向代理入口；直接公開且採 HTTP-01 時也用於驗證只有架構確實需要時才由 WAN 轉送；Tunnel 或 DNS-01 不應被誤解成一律要開
81/tcpNPM 管理 Web UI不可公開；只允許可信任區網或受控管理通道
443/tcpHTTPS 反向代理入口直接公開架構通常只轉送到 NPM；Tunnel 架構依通道設計，不另外留下不必要入口

WOOWTECH 的 config.yaml 將 80/tcp、81/tcp、443/tcp 分別對應到主機的 80、81、443；官方 NPM Setup 也把它們標為 Public HTTP、Admin Web、Public HTTPS。這描述的是服務用途，不代表三個連接埠都應對 WAN 公開。

路由器只談 WAN 入口：絕對不要建立外部 81 → Home Assistant 81 的轉送。若路由器已存在這條規則，先記錄影響範圍，再安全移除或停用該公開入口。

啟動與區網檢查

  1. 啟動 add-on

    在 add-on 資訊頁按「START／啟動」，等待狀態成為執行中。

  2. 先看簡短記錄

    只在本機檢查啟動是否完成，以及是否有連接埠衝突。記錄可能含位址、網域、憑證或請求資訊，不要公開貼出全文。

  3. 從可信任區網開啟 Web UI

    使用 add-on 的「OPEN WEB UI／開啟 Web UI」。若按鈕不可用，可從可信任區網嘗試 http://<HA區網位址>:81；不要把真實位址寫入公開筆記。

  4. 停在登入頁

    看到 NPM 登入畫面就代表本章檢查完成。預設帳密將在下一章使用，登入後要立即更改。

預設帳密尚未加固：在完成下一章前，保持 TCP 81 僅限可信任區網，且不要開始公開 Proxy Host。

公開前防線

  • 檢查路由器：不得有 WAN TCP 81 對應到 Home Assistant 或 NPM。
  • 檢查防火牆：TCP 81 只允許必要的可信任管理來源，不要允許任意網際網路來源。
  • 檢查 DNS：不要為管理介面建立公開記錄；真實網域與公私有 IP 均視為敏感資料。
  • 檢查分享內容：完整 add-on 記錄、憑證、密碼與 DNS API Token 不得放進 issue、聊天或截圖。
  • 尚未決定直接公開或 Tunnel 前，不要預先打開 WAN 80／443。

直接公開時，上游官方指南的基本流程是將 80、443 送到 NPM；WOOWTECH 文件另列出 Tunnel 不需路由器轉送的方案。兩者應依你的設計擇一落實，而不是把所有入口都打開。

安裝排錯

問題一：商店找不到 Woow Nginx Proxy Manager

確認倉庫網址完整、擁有者為 WOOWTECH，重新整理商店並查看 Home Assistant 是否能連到 GitHub。不要改加來路不明的鏡像。

問題二：顯示不支援此架構

核對系統是 amd64 或 aarch64。目前 config.yaml 未宣告其他架構；不要用錯誤映像強制安裝。

問題三：啟動失敗並提到 address already in use

通常是 TCP 80、81 或 443 已被占用。盤點同主機服務與 add-on 連接埠；先理解依賴，再決定調整哪一方。

問題四：add-on 執行中但 Web UI 打不開

先用「開啟 Web UI」，再從同一可信任區網檢查 http://<HA區網位址>:81。確認本機防火牆與 VLAN 規則，不要用 WAN 轉送來繞過問題。

問題五：安裝一直停住

檢查可用儲存空間、網路與 Supervisor 記錄中的明確錯誤。只摘錄必要行並遮罩敏感值，不要貼完整記錄。

常見問題

安裝時一定要先有網域嗎？
不用。你可以先在可信任區網安裝與加固帳號，等架構與 DNS 都準備好再建立 Proxy Host。
為什麼安裝後會看到三個連接埠？
80 與 443 是代理流量入口，81 是管理介面。它們被 add-on 發布到主機，不等於都要由路由器公開。
可以把主機 81 改成其他數字後公開嗎？
不可以用改號碼取代存取控制。無論外部號碼為何，管理介面都不應直接暴露到網際網路。
Home Assistant Container 能照這章安裝嗎？
不能。WOOWTECH README 的需求是 HAOS 或 Supervised；Container 使用者應依官方 NPM Docker 文件另行規劃。
